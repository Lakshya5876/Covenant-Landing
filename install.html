Covenant lives beside your project, never inside it.

projects/
├── your-project/   the repo you're governing
└── Covenant/       cloned once, installs into any repo beside it
    ├── CovenantMac/
    └── CovenantWin/

One clone. Install into as many repos as you govern — Covenant is never copied into any of them.

1

Clone Covenant next to your project

git clone https://github.com/Lakshya5876/Covenant.git
2

Enter your project and run the installer

cd your-project
../Covenant/CovenantMac/install.sh
Set-Location your-project
& '..\Covenant\CovenantWin\install.ps1'

The installer asks one question — real prompt, verbatim:

Which type of repository is this?
  [g] Greenfield — new project, no prior history
  [b] Brownfield — existing repository with code

Greenfield

Zero tolerance from commit one. Scaffolds a four-layer architecture — domain, application, infrastructure, presentation.

Brownfield

Maps your repo, freezes existing debt into a baseline, and enforces that debt can only shrink. Certified to 1M LOC.

3

Open Claude Code and initialize

claude
/init-governance

Interrogates you about your stack, drafts governance docs for your explicit approval, then generates a repo-specific CLAUDE.md and the enforcement hooks. Nothing is written without you signing off first.

!

The one step the installer can't do for you

Edit .github/CODEOWNERS to name a real reviewer, then turn on "Require review from Code Owners" under branch protection, in GitHub's settings. Until that's on, every control this installs is local-only.
